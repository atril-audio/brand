# `specs/` — las specs de ejecución

**La spec es la unidad de trabajo** (rulebook §1). Se generan con `/speckit-specify` y sus tareas
bajan a issues con `/speckit-taskstoissues`, como **sub-issues** de su épica en el
[Project `Pedalera`](https://github.com/orgs/atril-audio/projects/1).

Una spec dice **qué tiene que ser verdad al terminar** — criterios de aceptación verificables, no una
descripción del trabajo. El issue **apunta** acá; nunca copia el contenido.

Inmutables una vez ejecutadas: quedan como el registro de qué se pidió exactamente. Si el alcance
cambia a mitad de camino, se enmienda la spec **en el PR** y se dice por qué.
