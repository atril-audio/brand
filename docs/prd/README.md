# `prd/` — qué problema resuelve una pieza nueva

**El más delgado de los cuatro, a propósito.** Casi todo el trabajo de este repo es ejecución sobre
un sistema ya decidido, y va directo a [`../specs/`](../specs/).

Un PRD aquí se justifica cuando aparece una pieza que **cambia lo que un consumidor puede hacer**:
un tema claro, una salida iOS o Figma, un set de iconos nuevo. **No** cuando se agrega un token o se
corrige un valor.

Qué contesta, en este orden: **qué problema**, **de quién** (qué consumidor y en qué stack),
**qué NO es**, y **cómo se sabe que funcionó**. Vivo mientras se explora; congelado al comprometerse.

El documento vivo que dice qué hay **hoy** y cómo se consume es el [`README`](../../README.md) — hace
aquí el papel que el `PRD.md` hace en `pedalera`.
