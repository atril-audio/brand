# `rfc/` — propuestas de cambio al sistema

Un RFC es **una pregunta abierta con una propuesta**, no una decisión. Sirve cuando hay más de un
camino defendible y el debate vale escribirse: *¿qué formato de tokens? ¿qué build? ¿empaquetar las
tipografías o traerlas?*

**Ciclo de vida:** `propuesto` → `en revisión` → **`aceptado` (y nace un ADR)** o `rechazado`.
El RFC se queda con el debate; el ADR se queda con la decisión y su argumento. Cuando el RFC cierra,
**deja de ser lectura obligatoria** — el ADR es el que manda.

No hace falta un RFC para ejecutar algo ya decidido: eso es una spec.

**Formato:** `NNNN-slug.md` · el problema, las opciones **con sus costos**, la recomendación, y qué
haría falta para descartarla.
